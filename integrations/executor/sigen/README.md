# Sigen in Executor

This app connects the independent Sigen MCP service to Executor using a personal service account. It follows the Tesco integration's per-user account pattern. Credentials are opaque handles restricted to `sigen-api.barroncillian.workers.dev`. The service's owner credential is separate from both the Sigen password and the operator credential used for enrollment.

The provider's health check initializes MCP and lists tools with the credential, then confirms that the same requests fail without it. It does not run a tool. Known read-only tools need no Executor approval. `approve_command` always requests confirmation and includes the immutable before/after values plus the once/always choice. Preparing, executing an already approved saved command and revoking a grant do not prompt again; the service enforces the saved command, expiry, state checks and disable switch. Unknown tools always require confirmation, regardless of their metadata. The owner credential can approve commands; no separate human-only credential is required. Always grants cover future validated values for one operation and station until revoked; smart-load grants additionally bind the load key and path.
