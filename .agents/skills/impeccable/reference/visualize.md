# Visualize an open design choice

Use visual alternatives only when they clarify an actual unresolved composition.
The repository's Paper design remains visual authority. Do not generate a new
comp round for a precisely specified or already agreed surface.

Anchor alternatives on real product content, existing components and the agreed
palette/type system. Use representative viewport sizes; preserve recognizable
identity while varying meaningful structure. Avoid lifting unrelated reference
content into the product. Present enough alternatives to explain the trade-off,
not a fixed number. Tool unavailability never means the user approved a design.

When using existing Impeccable image tooling, preserve its sidecar/schema format
and actual asset provenance. Record only real approval, never manufacture
`approved: true` to satisfy a phase check. Compatible visual assets can stay
colocated; implementation status and acceptance remain in the owning plan.

Translate the agreed design into semantic, responsive, accessible components.
Keep text, controls and countable diagrams semantic; images are appropriate for
illustration/photography. Check the actual rendered result and meaningful states.
No compulsory visualization engine, concept lottery or extra approval loop is
introduced by this reference.
